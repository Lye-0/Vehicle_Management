# 車両顧客管理システム

顧客・車両・販売・整備・車検予定・入金を、店舗単位でまとめて管理するWebアプリケーションです。
顧客情報を起点に、車両の履歴、見積書・請求書、帳票PDF、入金状況まで一つの流れで確認できます。
ABACUSからの移行では、Windows用のローカル補助ソフトでABACUS本体フォルダーを解析し、内容を確認してからWebアプリへ登録できます。

## このシステムでできること

| 画面 | 主な機能 |
| --- | --- |
| **ダッシュボード** | 登録車両数、今月の売上、車検期限、未入金請求、入庫・出庫予定をまとめて確認 |
| **顧客・車両** | 顧客情報、複数の所有車両、添付ファイル、画像OCR、販売・整備履歴を管理 |
| **販売** | 販売見積書・請求書の作成、明細入力、税計算、帳票プレビュー、PDF出力 |
| **車検・点検・一般** | 車検・板金・一般整備の受付、作業明細、法定費用、入庫・出庫予定を管理 |
| **点検予定** | 車両に登録した車検満了日をカレンダーと一覧で確認 |
| **入金管理** | 販売・整備請求書の入金履歴、入金済み・未入金額、支払期限を管理 |
| **設定** | 店舗情報、税・端数処理、明細候補、アーカイブ、データ入出力、ユーザー・権限を管理 |
| **ABACUS移行** | ローカル補助ソフトでABACUSの顧客・車両・販売書類・整備書類・画像を解析し、Web登録前に確認 |

### 組織と権限

ログイン後は、現在選択している組織のデータを操作します。複数の組織に所属している場合は、サイドバーから利用組織を切り替えられます。

| ロール | 主な役割 |
| --- | --- |
| オーナー | 組織の利用開始、ユーザー管理、組織全体の設定管理 |
| 管理者 | 店舗業務、従業員管理、設定・データ操作の管理 |
| 従業員 | 顧客・車両、販売、整備、点検、入金などの日常業務。設定系の操作は組織の権限設定に従う |

## 業務の流れ

```mermaid
flowchart LR
  A["顧客・車両を登録"] --> B["販売または整備の書類を作成"]
  B --> C["明細・税・支払期限を入力"]
  C --> D["保存・PDF確認・出力"]
  D --> E["入金管理で入金を登録"]
  E --> F["完了確認・アーカイブ"]
  A --> G["車検満了日を登録"]
  G --> H["ダッシュボード・点検予定で確認"]
```

顧客・車両を一度登録すると、販売書類、整備書類、入金管理、車検予定から同じ顧客・車両を参照できます。

## 詳細機能

### 共通画面の使い方

- サイドバーから7つのメイン画面を切り替えます。
- 一覧画面では、検索、絞り込み、並び替え、対象データの選択を行います。
- 編集中のデータを保存せずに移動・新規作成する場合は、確認ダイアログが表示されます。
- 金額は円、日付は画面の表示形式、電話番号・郵便番号・走行距離は入力内容に応じて整形されます。
- `保存` は入力内容をデータへ反映し、`PDFで確認` は帳票を確認し、`PDF保存` または `出力` はファイルとして保存します。
- `アーカイブ` は通常一覧から書類を移動する操作です。完全削除とは異なり、設定画面から復元できます。

### 自動保存と端末内下書き

入力途中の内容を失わないため、自動保存と端末内の復元機能を用意しています。

<details>
<summary><strong>自動保存・端末内下書き・復元センター</strong> — 保存前の入力を確認して再開する</summary>

![端末内の入力を復元](docs/images/readme/draft-recovery.png)

#### 用語の違い

- `状態：下書き`：保存済みの販売・整備書類に設定する業務上の状態です。
- `端末内下書き`：ブラウザ端末に保存された、サーバーへ保存する前の入力データです。
- `自動保存`：編集中の内容をサーバーまたは端末へ保存する仕組みです。
- `復元センター`：端末に残った入力を、復元・保留・削除する画面です。

#### できること

- 既存の販売・整備書類を編集中に、自動保存の状態を確認できます。
- 新規書類、顧客登録、車両登録などの保存前入力を端末内へ保持します。
- 画面を離れた後に、復元センターから入力を選んで再開できます。
- 現在の入力を保留して別の入力を復元できます。
- 不要な端末内下書きを削除できます。
- 新規書類を保存またはキャンセルした後は、対応する未採番の端末内下書きを整理します。

端末内下書きは、販売・整備画面で表示される書類状態の`下書き`とは別のものです。

</details>

- 画像プレビューからOCRを実行し、認識したい領域を選択できます。
- OCRの結果は必ず原本と照合してから利用してください。
- 車両に紐づく販売・整備書類を車両履歴として確認できます。

#### 書類作成

`販売書類を作成`から、書類種別、顧客、対象車両を選んで`入力を開始`します。既存の顧客・車両だけでなく、新規顧客・新規車両を作成しながら開始できます。

#### 一覧と状態

- 書類番号、顧客名、車名で検索します。
- 書類種別を`すべて`、`見積書`、`請求書`で絞り込みます。
- 状態を`すべて`、`下書き`、`入金待ち`、`完了`で絞り込みます。

- 未完了書類と、作成月ごとの完了書類を確認できます。

#### 入力・計算・帳票

- 書類種別、状態、顧客、対象車両、書類日付、支払期限を入力します。
- 車両本体価格、値引等、工賃、法定費用、手続代行費用、実費・預託金、下取車、付属品・特別仕様などの明細を入力します。
- 数量、単位、単価、技術料・他、摘要、課税区分を明細ごとに管理します。
- 課税区分は`課税`、`非課税`、`対象外`です。
- 税率、課税対象額、消費税、非課税対象額、合計を帳票プレビューで確認します。
- `入力`と`プレビュー`を切り替え、帳票の内容を確認します。
- `PDFで確認`、`保存`、`PDF保存`、`アーカイブ`を使い分けます。

<details>
<summary><strong>設定</strong> — 店舗・帳票・データ・権限を管理する</summary>

![設定](docs/images/readme/settings.png)

設定画面には、利用者の権限に応じて次のサブタブが表示されます。

#### 店舗情報

帳票の発行元として利用する店舗名、郵便番号、住所、電話番号、FAX番号、適格請求書発行事業者番号、ロゴ画像を設定します。請求書に表示する振込口座・口座名義も管理できます。

#### 税・端数処理

消費税率、端数処理、販売書類の支払期限の初期日数を設定します。端数処理は`切り捨て`と`四捨五入`から選択できます。

#### 明細候補

販売書類の候補を次の3グループで管理します。

- 車両販売価格内訳
- 諸費用内訳
- 付属品・特別仕様明細

整備書類では、整備作業・部品候補を追加・名称変更・削除できます。登録した候補は、販売・整備書類の入力欄から選択できます。

#### アーカイブ

販売・整備画面でアーカイブした書類を検索・確認します。

- 通常一覧への復元
- 永久保存の設定・解除
- 保管期間の変更
- 完全削除

永久保存していない書類は、設定した保管期間を過ぎると自動削除の対象になります。完全削除は復元できないため、対象と確認ダイアログを確認してから実行します。

#### データ

##### CSV出力

顧客一覧、車両一覧、販売書類、整備書類、入金管理をUTF-8 CSVとして出力できます。

##### CSVインポート・移行

1. 取込対象を選択します。
2. CSVファイルを選択します。
3. `内容を確認`でプレビューとエラー行を確認します。
4. 問題がなければ`この内容を取り込む`を実行します。

対象は顧客一覧、車両一覧、販売書類、整備書類、入金管理です。ファイルは5MB以内、5,000行以内で使用します。取込後は追加・更新・スキップ件数を確認します。

ABACUSから出力した固定列CSVは、この通常のWeb CSVインポートへ直接取り込みません。ABACUS移行では、下記のローカル補助ソフトを使用してください。

##### バックアップ・復元

D1の組織データと、B2に保存された車両添付ファイルをバックアップします。オンライン（B2）、PC、または両方への手動保存、メモ、保管期間、永久保存、復元を利用できます。

定期バックアップはオンライン（B2）のみ利用でき、頻度は`毎日`または`毎週`です。PCの定期バックアップは実装されていません。復元前には安全バックアップを作成し、復元対象と復元後の件数を確認します。

#### 管理者・従業員

自分の表示名、メールアドレス＋パスワード、Googleログインを管理します。メール確認、パスワード変更、Googleログインの連携・解除もここから行います。

管理者・オーナーは、組織に所属する従業員の追加、ロール変更、利用停止、組織からの削除を行えます。従業員を追加したときに表示される初期パスワードは、画面を閉じると再表示できないため、安全な方法で本人へ伝えてください。

#### 権限管理

管理可能な利用者にのみ表示されます。従業員に対して、次の操作を許可するか設定できます。

- CSV出力
- 店舗情報の変更
- 税率情報の変更
- バックアップの作成・PC出力・インポート復元・B2復元
- バックアップの削除・永久保存・保持期限変更
- アーカイブの永久保存・保持期限変更

変更後は画面上部の`設定を保存`で反映します。

</details>

## ABACUSデータ移行（Windowsローカル補助ソフト）

ABACUS本体のポータブルフォルダーを、Windows用ローカル補助ソフトで解析します。補助ソフトは元のABACUSフォルダーを変更せず、候補確認と登録前パッケージの作成を行います。

> **事前準備（必須）**
>
> 補助ソフトを使用するには、選択するABACUS本体フォルダー内に、ABACUSから出力した次のCSVファイルが必要です。
>
> - `syaryou.csv`：車両一覧
> - `hanbai.csv`：販売書類
> - `seibi.csv`：整備書類
>
> ファイル名を変更せず、ABACUSの出力形式のまま配置してください。

ABACUSのCSVは見出し行を持たない固定列形式です。補助ソフトは販売33列、整備29列、車両一覧23列として検査し、行の構造や必須値を確認してから候補を作成します。

<details>
<summary><strong>ABACUSフォルダーを選択して解析する</strong> — CSVと画像の移行準備を始める</summary>

![ABACUSインポートの開始画面](docs/images/readme/companion-import-start.png)

1. ABACUS本体フォルダーを選択します。
2. 生成物を保存する通常のフォルダーを選択します。
3. `解析を開始`を押します。

解析では、`syaryou.csv`、`hanbai.csv`、`seibi.csv`を読み取り、顧客・車両・販売書類・整備書類の候補を作成します。

FP5内の車検証画像も通常の解析経路で復元し、車台番号などの車両識別情報を使って対応付けます。原本のABACUSフォルダーとCSVは変更しません。

</details>

- 顧客、車両、販売書類、整備書類の関係をキャンバスで確認します。
- 自動紐付けされた車両・書類を確認します。
- 顧客統合候補をグループとして確認します。
- 車両や書類をドラッグして、手動で紐付けを変更できます。
- 未確定トレイへ移動した項目は、登録前に確認できます。
- 今回の移行から除外する顧客・車両・書類は、ごみ箱で管理できます。

この段階では、候補を確認・編集するだけで、Web側の顧客・車両・書類は登録されません。

</details>

<details>
<summary><strong>顧客マッチングUIでおすすめを確認する</strong> — 顧客単位で候補を判断する</summary>

![ABACUS移行の顧客マッチングUI](docs/images/readme/companion-matching.png)

顧客を1件ずつ選択し、その顧客に関係するおすすめを確認します。

- 顧客統合、車両、書類のおすすめを分類して表示します。
- 一致項目、差異、情報なし、競合を確認できます。
- おすすめは自動確定されません。
- 内容を確認して`承認`、`保留`、`却下`を選択します。
- 採用する顧客名や住所などを顧客情報プレビューで決定します。
- グラフUIと顧客マッチングUIは同じ作業状態を共有します。

同じ顧客に複数の車両がある場合も、車両ごとの候補を別々に確認できます。

</details>

<details>
<summary><strong>インポート内容を確定して登録前パッケージを作成する</strong> — Webへ渡す内容を固定する</summary>

![ABACUS登録前パッケージ作成](docs/images/readme/companion-ready-package.png)

1. 顧客統合、車両・書類の紐付け、未確定項目、除外項目を確認します。
2. `インポート内容を確定`を押します。
3. `確定内容から登録前パッケージを作成`を押します。

作業フォルダーには、作業途中の`work`とWebへ渡す完成品の`ready`を分けて保存します。`work`はWebへ送信せず、`ready`のマニフェストとファイルだけをWeb側で検証します。

この段階でも、Web API、D1、画像ストレージ、元のABACUSフォルダーへの登録・書き込みは行いません。

</details>

<details>
<summary><strong>Web側で登録前パッケージを確認して登録する</strong> — 最終確認後に本番データへ反映する</summary>

![Web側のABACUS登録前パッケージ](docs/images/readme/web-abacus-registration.png)

1. Webアプリの`設定`から`データ`を開きます。
2. `ABACUS登録前パッケージをプレビュー`で、補助ソフトが作成したフォルダーを選択します。
3. ファイルのSHA-256、顧客・車両・書類・画像の件数、紐付け関係を確認します。
4. Web APIの登録前再検証が完了したことを確認します。
5. 確認文字列を入力し、最終登録を実行します。

登録ボタンを押すまでは、顧客・車両・書類の登録や画像アップロードは行われません。画像処理だけ失敗した場合は、同じパッケージから失敗分を再試行できます。

</details>

### 複数車両と車両なし書類

ABACUSでは、同じ顧客に複数の車両がある場合、車両ごとに別のCSV行として出力されます。補助ソフトはそれぞれを別の車両候補として読み取り、Web登録時には1人の顧客へ複数車両を紐付けます。

販売・整備書類に車両情報がない、または車両一覧と一意に一致しない場合は、顧客直結の「車両なし書類」または未確定書類として確認対象になります。

## 開発者向け情報

<details>
<summary><strong>ローカル開発環境を起動する</strong></summary>

ルートディレクトリで次を実行します。

```powershell
pnpm dev
```

次の3つが同時に起動します。

- Firebase Auth Emulator（`http://127.0.0.1:9099`）
- Cloudflare Workers API（`http://127.0.0.1:8787`）
- Vite Web（`http://localhost:5173`）

API起動時に開発用ローカルD1の未適用マイグレーションを自動適用します。手動で適用する場合は次を実行します。

```powershell
pnpm migrate:local
```

個別に起動する場合は次を使用します。

```powershell
pnpm dev:auth
pnpm dev:api
pnpm dev:web
```

詳細は [ローカル開発環境](docs/local-development.md) と [開発・本番環境の分離](docs/environment-separation.md) を参照してください。

</details>

<details>
<summary><strong>環境変数を設定する</strong></summary>

環境変数の実ファイルはGitへコミットしません。値はこのREADMEやソースコードへ記載せず、安全な保管場所から設定します。

### Web

開発用は`apps/web/.env.development`、本番用は`apps/web/.env.production`です。

```text
VITE_APP_ENV
VITE_FIREBASE_API_KEY
VITE_FIREBASE_AUTH_DOMAIN
VITE_FIREBASE_PROJECT_ID
VITE_FIREBASE_STORAGE_BUCKET
VITE_FIREBASE_MESSAGING_SENDER_ID
VITE_FIREBASE_APP_ID
VITE_FIREBASE_AUTH_EMULATOR_URL（開発用のみ）
VITE_API_BASE_URL
```

### API

開発用は`apps/api/.dev.vars.development`、本番構成のローカル確認用は`apps/api/.dev.vars.production`です。

```text
APP_ENV
DATA_ENV
FIREBASE_PROJECT_ID
FIREBASE_AUTH_EMULATOR
FIREBASE_WEB_API_KEY
FIREBASE_ADMIN_SERVICE_ACCOUNT_JSON
INITIAL_SETUP_KEY
CORS_ORIGIN
B2_ENDPOINT
B2_REGION
B2_BUCKET
B2_KEY_ID
B2_APPLICATION_KEY
```

`.dev.vars.production`はローカル確認用です。実際に本番Workerへ設定するSecretはCloudflare/Wrangler側で管理します。

</details>

<details>
<summary><strong>本番用コマンド</strong></summary>

本番操作は、開発用の`pnpm dev`とは別の明示的なコマンドです。対象環境と実行内容を確認してから使用してください。

```powershell
# 本番用Webをビルドして、本番Workerへデプロイ
pnpm prod
```

`pnpm prod`は、本番用Webのビルドと本番Workerへのデプロイをまとめて実行します。スキーマ変更を伴う場合は、適用内容を確認してから次のコマンドを個別に実行します。

```powershell
# 本番用Webをビルド
pnpm build:production

# 本番D1へマイグレーションを適用
pnpm migrate:production

# 本番Workerへデプロイ
pnpm deploy:production
```

</details>

<details>
<summary><strong>ローカル補助ソフトの入手・ビルド</strong> — ABACUS移行用ポータブル版を使用する</summary>

利用者はGitHub Releasesから、`VehicleManagement.Companion-vX.Y.Z-portable-win-x64.zip`をダウンロードして使用します。展開した補助ソフトは、ABACUS本体フォルダーへインストールせず、通常の作業フォルダーから起動してください。

開発者がポータブル版を作成する場合は、リポジトリのルートで次を実行します。

```powershell
.\apps\companion\scripts\publish-portable.ps1 -Version 1.0.0
```

作成したZIPをGitHub Releasesへ添付し、`vX.Y.Z`形式のタグと対応するバージョンを案内します。リリース前には、必須CSV（`syaryou.csv`、`hanbai.csv`、`seibi.csv`）を置いたABACUSフォルダーで解析から登録前パッケージ作成までを確認してください。

</details>
