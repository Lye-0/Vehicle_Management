# ABACUSローカル補助ソフト

ABACUSからのデータ移行など、Windows上でのみ実行できる処理をWebアプリから分離して担当する.NET 10 WPFアプリです。

## 実装済みの範囲

- WPF補助ソフトの起動
- LegacyHostの別プロセス起動・停止
- ユーザー限定Named Pipeによる疎通確認
- WPF終了時のLegacyHost終了
- 保存用ABACUSフォルダーの読取検査
- SHA-256検証付き作業用コピーの作成
- コピー後の保存用原本の再検証
- コピー側ABACUSの起動
- x64 LegacyHostからのUI Automation認識確認
- 販売・整備TABファイルの構造分析
- 検証マニフェストを使った既存作業用コピーの再検証
- コピー側ABACUSの画像画面に対するUI Automation要素診断
- ABACUSを画面側で終了した場合の終了状態再確認
- FileMaker ActiveXのx86登録・実行中インスタンスの読み取り診断
- `BackUp-5.fp5`のFileMaker 5.0ヘッダーとJPEG候補の読み取り診断
- 登録前候補パッケージの再検証と顧客・車両・書類グラフの読み取り専用プレビュー

保存用原本は読み取り専用で扱い、ABACUSを起動するのは検証済みの作業用コピーだけです。

## 構成

```text
apps/companion/
├── VehicleManagement.Companion.slnx
└── src/
    ├── VehicleManagement.Companion/   WPF本体・プロセス管理
    ├── VehicleManagement.LegacyHost/  ABACUS処理を隔離するプロセス
    └── VehicleManagement.LocalProtocol/ Named Pipe通信契約
```

LegacyHostのビット数はまだ固定していません。Gate 2でx64 LegacyHostから32bit ABACUSをUI Automationできることを目視確認した後に決定します。

## 作業用コピーの安全策

- 必須ファイルの存在、ファイル数、合計サイズ、実行ファイル形式を検査します。
- リンクや再解析ポイントを拒否し、フォルダー外のファイルを読み込みません。
- 全ファイルのSHA-256を計算します。
- コピー先には毎回新しい`ABACUS-Work-yyyyMMdd-HHmmss`フォルダーを作り、既存ファイルを上書きしません。
- コピーした各ファイルを検証し、最後にコピー全体と保存用原本を再検査します。
- コピー先の隣に検証用の`.manifest.json`を保存します。
- キャンセルまたは失敗したコピーは起動対象にしません。

1GBを超えるファイルを複数回読み取るため、検査とコピーには時間がかかります。処理中もキャンセルできます。

## 書類データ分析

| ファイル | 内容 | 列数 | 主要な識別列（0始まり） |
| --- | --- | ---: | --- |
| `BackUp-2.tab` | 販売書類 | 102 | 顧客名0、登録番号13、車台番号22、書類番号51 |
| `BackUp-3.tab` | 整備書類 | 158 | 顧客名0、登録番号11、車台番号14、書類番号77 |

パーサーはShift-JISの不正バイト、列数違反、上限を超えるファイル・行・フィールド、未許可の制御文字、リンクを拒否します。ABACUS内で確認されたU+0004、U+000B、U+001Dだけは既知の内部区切りとして受け付け、後続変換で空白へ正規化します。

顧客名が空欄の行は構造エラーにはせず、取込候補から除外して件数を集計します。車両候補件数は車台番号、登録番号、顧客＋車両情報の順で保守的に算出しますが、この段階では顧客や車両を統合しません。

## 顧客・車両の紐付けプレビュー

顧客名だけでは自動統合しません。同じ正規化名の書類について、次のいずれかが一致する場合だけ同じ顧客候補にまとめます。

- 電話番号
- 住所
- 車台番号
- 車台番号との競合がない登録番号

同姓同名でも上記の根拠が一致しなければ別候補にし、競合一覧へ表示します。

車両は車台番号を最優先し、次に登録番号を使用します。同じ登録番号に異なる車台番号がある場合は、登録番号の再利用や入力差異の可能性があるため自動統合しません。同じ車両識別子が複数顧客に現れる場合も、名義変更・過去所有の可能性を含む競合として表示します。

このプレビューは候補と競合の確認専用であり、顧客・車両・書類をデータベースへ登録しません。

## ActiveXとfp5格納画像の診断

Gate 6Cで標準WindowsメニューとFileMakerの内部ウィンドウを確認した後、x86の別プロセスから`FMPRO.Application`の登録と実行中インスタンスだけを読み取ります。スクリプトの実行、メニュー操作、レコードの編集・保存は行いません。現在のABACUS Runtimeではx64・x86の両方で`FMPRO.Application`登録が確認できないため、ActiveX経由のエクスポートは採用しません。DLLの登録やシステムレジストリの変更も行いません。

Gate 6Dでは、ActiveXを使わずに保存用原本の`BackUp-5.fp5`を読み取り専用で検査します。FileMaker Pro 5.0のヘッダーとJPEG開始・終了マーカーをストリーム走査し、候補のファイル内位置、サイズ、読み取れる画像寸法だけを表示します。ファイルサイズは2GiB、JPEG候補は20,000件、候補1件は256MiB、画面表示は先頭100件までに制限します。画像本体の保存・顧客情報の表示・fp5の書き込みはこのGateでは行いません。

実機の保存用原本では、`BackUp-5.fp5`（約353MiB）からJPEG候補162件（合計約334MiB）が検出されました。これは画像の格納場所が存在することを示す診断結果であり、候補と車両を紐付ける仕様や元画像の安全な抽出方式は次のGateで確定します。

Gate 6Eでは、6Dの候補一覧から利用者が1件だけ選択し、ABACUSフォルダーの外側に新規JPGとして検証出力します。出力直前に現在のファイル範囲、JPEG開始・終了マーカー、標準JPEGのSOF/SOS/EOI構造、最大256MiB、最大5,000万画素、WPFのJPEGデコーダー、SHA-256を再検証します。FileMaker内部の分割ブロックを標準JPEGとして誤って保存しないよう、複数フレームやスキャン中の予期しないマーカーを検出した候補は保存せず、既存ファイルも上書きしません。実機の候補はこの構造検証を通過せず、灰色の仮画像を生成する結果になったため、元画像の抽出方式としては採用しません。実画像はGate 5D/5Eの画像表示ウィンドウの読み取りを利用するか、FileMakerコンテナの正式な解析方式を別途確定します。これは抽出方式の診断であり、車両との自動紐付けや一括出力ではありません。

## 車両画像の抽出準備

「画像抽出準備」タブでは、作成済みの`ABACUS-Work-*`フォルダーを隣接する検証マニフェストおよび保存用原本と照合し、許可条件を満たした場合だけ起動対象にします。

FileMaker Runtimeは、コピー側ABACUSを起動・操作しただけでも使用した`abx-cs-??.ucs`の管理情報を書き換えます。再利用時は保存用原本が作成時のハッシュを維持していること、ファイル構成・サイズが同一であること、他の全ファイルが原本と一致することを検証します。原本直下の`abx-cs-英数字2文字.ucs`だけは、サイズ不変、1ファイルあたり差分4,096バイト以内、全対象の合計差分16,384バイト以内に限定して許容します。`sbx-*`、実行ファイル、DLL、TABなどの変更は拒否します。

Gate 5Aでは、コピー側ABACUSで車両画像を手動表示した後、LegacyHostが標準UI Automationで認識できる要素を最大30件まで読み取り診断します。画像出力、キー入力、クリック、ABACUSレコードの変更は行いません。診断結果を確認してから、次のGateで対象要素に限定した1件抽出方式を決定します。

実機診断ではFileMakerのMDI子ウィンドウまでしかUI Automationに公開されず、画像フィールドを個別認識できませんでした。Gate 5Bでは利用者がABACUS上で車両画像を手動選択して`Ctrl+C`を行い、補助ソフトはクリップボードの形式名、標準画像として取得可能か、画像寸法、ファイル参照の件数と拡張子だけを診断します。画像本体の保存やプレビューはまだ行いません。

Gate 5Cでは、Gate 5Bで標準画像として診断した同一クリップボード内容を1件だけPNGへ変換します。最大5,000万画素・256MBに制限し、PNGとして再読込できることと寸法一致を保存前に検証します。保存用原本・作業用コピーの内部は保存先にできず、毎回新しいファイル名を作成して既存ファイルを上書きしません。

ABACUSでは画像フィールドを選択・コピーできないことが確認されたため、Gate 5Dでは`abx-cs-sk`のMDI子ウィンドウだけを対象に`PrintWindow`で表示内容を取得します。取得前にウィンドウが診断済みABACUSプロセスに属することを再検証します。これは画面表示解像度のPNGであり、FileMakerコンテナ内の元画像データではありません。

Gate 5Eでは、`PrintWindow`が返す右側・下側の未描画領域を除去します。末尾のほぼ黒一色の行・列を先に除外し、その内側にある非白色の描画範囲へ6ピクセルの余白を付けて切り出します。検出領域が64×64未満または元画像の5%未満の場合は異常検出として自動切り出しを適用しません。

Gate 5Fでは、非白色領域を単純にすべて包含せず、縦・横それぞれで最大の連続描画領域を画像本体として採用します。これにより画像本体から離れた右端のABACUS表示ラベルを除外します。また、画像上端の一定範囲だけを対象に、十分な高さを持つ高密度な操作領域とその直後の空白を検出できた場合に限り、サイズ切替ボタンを含む上部ツールバーを除外します。条件に一致しない通常画像ではツールバー除外を行いません。

Gate 5Gでは、保存した画像1件に対して利用者がABACUS画面で確認した車台番号または登録番号を入力し、画像と同じ保存先へ確認専用の`ABACUS-image-link-*.json`を新規作成します。車台番号を優先し、登録番号だけの場合は再利用の可能性があるため照合方式を`registration`として要確認扱いにします。画像ファイルのサイズ・SHA-256、画像寸法、原本・作業用コピーの検証済みフォルダー指紋を記録しますが、顧客・車両のデータベース登録、APIへのアップロード、ABACUSフォルダーへの書き込みは行いません。マニフェスト作成前に識別子を確認するダイアログを表示し、識別子が空欄の状態では作成できません。

Gate 5Hでは、画像保存先のマニフェストとABACUSの`syaryou.csv`／`syaryou2.csv`を読み取り専用で照合します。車両一覧は固定23列（顧客名0、メーカー11、車名12、型式17、車台番号18、登録番号19）としてShift-JIS・引用符・列数・行数・フィールド長・制御文字・ファイルSHA-256を検証します。車台番号と登録番号が同じ行に一致した場合だけ一致候補とし、登録番号だけ、短い・数字だけの車台番号、複数行一致、識別子競合、顧客名不一致、未一致は要確認または競合として自動登録候補から除外します。`syaryou.csv`と`syaryou2.csv`の行を顧客名で統合せず、重複候補をそのまま表示します。画像ファイルのSHA-256も再検証し、マニフェストや画像が改変されている場合は不正扱いにします。この段階でもデータベース登録・APIへのアップロード・CSVへの書き込みは行いません。

Gate 5Iでは、Gate 5Hで一意の候補になった「一致」または「要確認」の行を利用者が目視確認し、選択した場合だけ確認済み証跡`ABACUS-image-approval-*.json`を画像保存先へ新規作成します。承認直前にマニフェスト・画像・車両一覧CSVを再読込し、画像SHA-256、マニフェストSHA-256、CSVファイルSHA-256、CSV行番号と行内容を再検証するため、画面表示後の差し替えは承認されません。証跡は原子的に作成し、同じマニフェストの二重承認を拒否します。これは人による確認事実を残す段階であり、顧客・車両の登録、APIへのアップロード、ABACUSフォルダーへの書き込みは引き続き行いません。

Gate 5Jでは、`human-reviewed`の確認済み証跡を再検証し、確認済み画像と対応する`syaryou.csv`／`syaryou2.csv`の行だけを新しい`ABACUS-Image-Registration-Preview-*`フォルダーへコピーします。`manifest.json`には確認済み証跡・画像・CSV行のハッシュ、CSVファイル名・行番号、車両識別子、顧客名、画像相対パスを登録前候補として保存します。顧客名だけで同姓同名を統合せず、候補IDは証跡・マニフェスト・CSV行から決定します。画像コピー後とマニフェスト保存後に再読込検証を行いますが、この段階でも顧客ID・車両IDの解決、データベース登録、API送信、ObjectStorageへのアップロード、ABACUSフォルダーへの書き込みは行いません。

Gate 5Kでは、Gate 5Jの`ABACUS-Image-Registration-Preview-*`を入力として、既存WebインポートAPIの見出しに合わせたUTF-8（BOM付き）`customers.csv`と`vehicles.csv`、画像対応表`image-attachments.json`を新しい`ABACUS-Web-Import-Preview-*`へ作成します。ABACUSの元号年・日付・数値・記録簿表記は、APIが受け付ける値へ変換できた場合だけ正規化し、原文と出典を備考へ残します。候補ごとに決定的な仮の顧客ID・顧客番号・車両IDを発行し、顧客名による既存顧客への自動照合や同姓同名の自動統合は行いません。同じ顧客名が複数候補に現れる場合は、複数車両か同姓同名かを手動確認する警告をマニフェストへ記録します。CSVの作成後もWeb API送信、顧客・車両の登録、画像アップロードは行わず、画像対応表は次段階の手動アップロード用です。

Gate 5Lでは、Gate 5Kの候補CSVを再検証して顧客・車両の一覧を表示し、顧客グループキーを人が確認・編集できるようにします。初期値は候補ごとに別顧客です。同じ顧客に複数車両があると確認した行だけ同じキーへ変更し、異なる顧客名を同じキーへ設定する操作は拒否します。確定時には`ABACUS-Web-Import-Mapping-*`フォルダーへ`mapping.json`（`human-reviewed`）を新規作成し、入力パッケージのSHA-256、候補ID、車両CSV行、画像、顧客グループキー、判断理由を記録します。この段階でもCSVの書換え、顧客・車両の登録、API送信、画像アップロードは行いません。

Gate 5Mでは、Gate 5Lの`human-reviewed`対応付け証跡と入力候補パッケージを再検証し、`ABACUS-Web-Import-Registration-Preview-*`フォルダーへ登録前パッケージを作成します。顧客グループごとに決定的な顧客ID・顧客番号を発行し、同じ顧客に複数車両がある場合は顧客CSVを1行、車両CSVを複数行へ変換します。車両ID、画像、画像SHA-256、候補ID、対応付け判断、CSV行の出典は保持し、`image-attachments.json`の顧客ID・車両IDも出力後の値へ更新します。出力マニフェストは対応付け証跡と入力候補マニフェストのSHA-256を記録し、CSV・画像・JSONを再読込検証します。この段階でもWeb API、D1、Object Storage、ABACUSフォルダーへの接続・書込は行いません。

Gate 5Nでは、Webアプリの設定画面からGate 5Mの`ABACUS-Web-Import-Registration-Preview-*`フォルダーを選択し、ブラウザー内でマニフェスト、全ファイルのサイズ・SHA-256、CSVのUTF-8・見出し・列数、画像対応表の参照先を再検証します。検証に合格した`customers.csv`と`vehicles.csv`だけを既存Web APIの`preview`エンドポイントへ送信し、API側の入力エラーと件数を表示します。`commit`エンドポイントは呼び出さず、顧客・車両の登録、画像アップロード、D1・Object Storageへの書込は行いません。フォルダー内の画像はローカル検証と対応表確認のために読み取るだけで、Webへ送信しません。実登録の前に、次段階で人が最終確認する導線を設けます。

Gate 5Oでは、Gate 5Nのプレビューと確認文字列`ABACUS登録を実行`が一致した場合だけ、管理者向けの登録APIを呼び出します。サーバー側でもマニフェストのSHA-256、固定ヘッダー・列数・値形式、顧客の車両台数、画像対応表、既存IDの内容を再検証します。顧客と車両はD1の一括処理で同時に登録し、同じ仮IDの内容が完全一致する再試行は冪等に更新扱いとします。画像は20MB以下のPNG/JPEGを1件ずつSHA-256・シグネチャ検証してB2へ保存し、表示・ダウンロード用ファイル名には`車検証_`を先頭に付けます。途中で失敗した画像だけ同じパッケージから再試行できます。画像アップロードは顧客・車両のD1登録とは別処理であり、ABACUS原本は変更しません。

## 永続ローカル移行パッケージ

Gate 6Aでは、利用者が選択した通常フォルダーへ`ABACUS-Migration-Preview-*`フォルダーを新規作成します。開発中のWorkersプロセスが持つ一時ファイルシステムは永続保存先として扱いません。将来、開発用または本番用ObjectStorageへ接続する前段として、補助ソフト側に永続成果物の境界を置きます。

この段階で出力する`manifest.json`は、販売・整備TABファイルのファイル名、サイズ、SHA-256と、顧客・車両・書類候補、除外、競合の集計だけを含みます。顧客名・住所・電話番号などの行データ、画像、変換済みデータは含めず、`status`を`preview-only`、`dataFiles`と`imageFiles`を空配列に固定します。書込後にマニフェストを再読込して内容を検証し、既存ファイルは上書きしません。

Gate 6Bでは、ABACUSが出力する見出しなし固定列CSVを読み取り専用で診断します。販売は33列、整備は29列、車両一覧は23列として扱い、Shift-JISの不正バイト、引用符、列数、5MB・5,000行の上限、フィールド長、制御文字、主要な必須値を検証します。`syaryou.csv`と`syaryou2.csv`が同時に存在する場合、同一車両の重複可能性があるため自動結合しません。この段階では登録用データを出力しません。

Gate 6Bの診断画面では、各CSVの先頭データ行を0始まりの列番号付きで表示します。金額・明細・日付の位置を人が確認した後、車両一覧が1ファイルだけで診断に合格した場合に限り、「固定列CSVから登録前候補を作成」を実行できます。作成先には`ABACUS-Export-Import-Preview-*`を新規作成し、`customers.csv`、`vehicles.csv`、`sales.csv`、`maintenance.csv`、`manifest.json`を保存します。これは既存Webインポート形式に合わせた読み取り専用の候補であり、Web API、D1、Object Storage、画像アップロード、ABACUS原本への書き込みは行いません。

候補化では、車両一覧の各行を独立した車両候補として扱います。顧客名だけでは統合せず、住所がある場合は顧客名と住所を候補キーに含め、住所のない行には出典ファイル名と行番号を含めます。書類の車台番号・登録番号が車両一覧の1行に一致し、顧客名（および双方に住所がある場合の住所）も矛盾しない場合だけ車両へ仮紐付けします。複数候補、識別子競合、顧客情報の不一致は「要確認」として自動紐付けを保留し、整備書類は車両が一意に確定しない行を候補CSVから除外します。顧客名が空欄の行はエラーにせず無視し、除外件数を画面とマニフェストへ記録します。販売・整備の税額と明細列は、ABACUSの確定位置を別途確認するまで未確定として警告を残します。

候補パッケージ作成後は「候補パッケージを再検証」から同じフォルダーを読み込み、マニフェストと4つの候補CSVを再検証できます。ファイルの存在、リンク属性、UTF-8、固定見出し、列数、行数、サイズ、SHA-256が一致しない場合は一覧を表示せず停止します。合格後は出典CSVの行番号、顧客名、車両名、書類番号、判定、判定理由を一覧で確認できます。これは最終的なグラフ型の手動紐付けUIへ渡す前の再検証段階であり、現時点では候補の編集や登録は行いません。

再検証に合格すると「顧客・車両・書類のグラフ型確認」が表示されます。左側で顧客を選ぶと、顧客から車両、車両から書類へ関係をたどれます。右側には選択した顧客・車両・書類の詳細と判定根拠を表示し、画面下部には未確定車両・未確定販売書類・未確定整備書類を分けて表示します。マニフェストが一意一致と判定した書類は緑色の実線、要確認・未一致・除外は点線と色で区別します。線はブロックの移動中もノードIDを基準に追従します。グラフ上のホイール操作はタブ全体のスクロールへ渡し、キャンバスの空白を左ドラッグした場合だけキャンバスを移動します。移動範囲は、表示領域内に少なくとも1つのブロックが残るよう制限します。同姓同名の顧客は顧客IDが異なる限り別ブロックのままです。書類カードのハンドル、または未確定トレイのカードを車両へドラッグすると、画面上だけの手動仮紐付けとして車両側へ青い点線を表示します。元の候補CSV、マニフェスト、ABACUS原本は変更せず、画面を再読込すると仮紐付けは破棄されます。同じ正規化顧客名の候補が複数ある場合は比較画面を開き、電話・メール・住所などを候補ごとに選択して統合プレビューを保存できます。統合プレビューは画面上だけの状態であり、顧客ID、候補CSV、データベース、APIを変更しません。手動判断の永続的な証跡保存は次段階で追加します。

GUIを使わず、個人情報を出力せずに集計だけを確認する場合は次を使用します。

```powershell
dotnet run --project apps/companion/src/VehicleManagement.AbacusImport.Cli/VehicleManagement.AbacusImport.Cli.csproj -- "<ABACUSフォルダー>"
```

固定列CSVの診断結果と先頭データ行の列サンプルを確認する場合は、次を使用します。出力はローカルの端末に表示するだけで、CSVやABACUSフォルダーは変更しません。

```powershell
dotnet run --project apps/companion/src/VehicleManagement.AbacusImport.Cli/VehicleManagement.AbacusImport.Cli.csproj -- --legacy-export "<ABACUSのCSVフォルダー>"
```

## ビルドと起動

リポジトリルートから実行します。

```powershell
dotnet build apps/companion/VehicleManagement.Companion.slnx
dotnet run --project apps/companion/src/VehicleManagement.Companion/VehicleManagement.Companion.csproj
```

GUIを表示せず通信・終了処理を検証する場合は、ビルド後の実行ファイルに`--self-test`を指定します。

```powershell
apps/companion/src/VehicleManagement.Companion/bin/Debug/net10.0-windows/VehicleManagement.Companion.exe --self-test
```

終了コード`0`なら、LegacyHostの起動、ハンドシェイク、ping、正常終了に成功しています。
